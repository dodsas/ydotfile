# 한국어 운영문서 작성 스타일

`README.md` / `deploy/README.md` / `deploy/SETUP.md` 의 톤. 새 운영문서를 쓸 때 이 규칙 따른다.

## 전체 구조 (긴 가이드)

1. **한 줄 요약** — 무엇/왜. 화살표 다이어그램이면 더 좋음
2. **사전 요구사항** 표 — 항목 / 버전·비고
3. **설치 및 실행** — 복붙 가능한 블록 단위
4. **환경 변수** 표 — 변수 / 기본값 / 설명
5. **API/명령** 레퍼런스 — 엔드포인트당 요청·응답·HTTP 코드
6. **End-to-end 예제** — curl / 언어별
7. **운영·보안 체크리스트** — `- [ ]` 박스로
8. **트러블슈팅 표** — 증상 / 원인·해결
9. **라이선스 / 비고**

## 짧은 SETUP 체크리스트 형식 (대안)

`☐ N단계 — 제목` 헤더로 각 단계 분리. 각 단계 끝에 "검증:" 한 줄. 마지막에 트러블슈팅 표.

## 문장 규칙

- **단정형**. "~합니다" 보다 "~한다" 우세. 명령형은 "~할 것" / "~하세요" 혼용 가능
- **불필요한 어미 컷**. "~인 것 같습니다" / "~할 수도 있습니다" 같은 hedging 지양
- **영문 명사는 영문 그대로**: container, rootless, webhook, healthcheck, JWT, subprocess
- **마침표 일관성**: 표 셀 안에서는 마침표 생략, 문장형 블록에서는 사용
- **이모지/장식 최소**: ✓ ✗ ⚠ 💡 정도만. 본문엔 안 씀

## 표 사용 적극

- 환경변수 / 트러블슈팅 / 비교 표를 본문 산문보다 우선
- 헤더는 보통 2–4 컬럼. 5컬럼 넘으면 가독성 떨어짐

## "왜 / 주의" 인용 블록

비-자명한 결정·함정에는 `>` blockquote 로 분리:

```markdown
> 💡 **rootless Podman 권한 매핑** — compose.yml 에 `userns_mode: "keep-id"` 가 설정되어 …
```

핵심 패턴:
- **굵은 키워드** + em-dash + 설명. 한 단락.
- 함정은 `⚠` 또는 `> ⚠`. 권장은 `💡`. 성공/체크는 `✓`.

## 코드 블록

- 언어 태그 명시: ` ```bash `, ` ```python `, ` ```yaml `
- 복붙 가능해야 함. 변수는 `<…>` 로 명시: `ssh dodsas@<podman-host>`
- 긴 명령은 `\` 줄바꿈 + 4칸 들여쓰기

## 트러블슈팅 표 패턴

```markdown
| 증상 | 원인 / 해결 |
|---|---|
| `Claude CLI not found at 'claude'` | CLI 미설치 또는 PATH 미반영. `CLAUDE_CLI_PATH` 에 절대경로 지정 |
```

- 좌측: 실제로 보게 될 **에러 메시지/증상** (백틱)
- 우측: 원인 한 단어 + 해결 명령. 마침표 없음
- 5–10 행이 적정

## 안 해야 할 것

- 페이지 끝에 "본 문서는 …" 같은 작성자/날짜 메타 (git blame 으로 충분)
- TOC 자동 생성 표시 (`<!-- TOC -->` 류)
- 같은 명령을 본문·예제·체크리스트에 3번 복붙 — 한 곳에만 두고 다른 곳은 `§N 참조` 로 링크
- "이 부분은 추후 보완 예정" 같은 미완 표시 (할 거면 지금 쓰고, 아니면 빼기)

## 커밋 메시지 톤

- 영문 prefix + 한국어 본문 혼용: `fix(compose): ~/.claude 마운트에서 :ro 제거하여 OAuth 토큰 refresh 허용`
- prefix: `feat / fix / chore / docs / refactor / test`
- 본문은 "왜" 위주. "무엇" 은 diff 가 말해줌
